# QuantumHub.Service

Exe хаба. Намеренно почти пустой: вся логика в `QuantumHub.Core`.

Это фоновый процесс в сессии пользователя, а не служба Windows. Почему, объяснено в статье
об архитектуре (`docs/ARCHITECTURE.md`).

Без окна и без консоли (`WinExe`). Второй экземпляр просто завершается с кодом 3. Если хаб падает, причина остаётся в `logs\crash.log`.

## Аргументы

| Аргумент | Что делает |
|---|---|
| `--console` | Показывает журнал в консоли |
| `--root <папка>` | Папка программы, по умолчанию папка exe |
| `--data <папка>` | Папка данных, по умолчанию `%APPDATA%\QuantumHub` |
| `--instance <имя>` | Запустить отдельный экземпляр, например для экспериментов |
| `--tcp <порт>` | Слушать ещё и loopback TCP. `0` выбирает свободный порт |
| `--watch` | Запустить сторожа: он держит хаб запущенным и поднимает его после падений |

Для отладки удобно так:

```bash
QuantumHub.Service.exe --console --instance dev --data ./dev-data
```

## Настройки

Лежат в `%APPDATA%\QuantumHub\config\hub.jsonc` и меняются на странице настроек:

| Ключ | Что это | По умолчанию |
|---|---|---|
| `language` | `auto`, `ru` или `en` | `auto` |
| `logLevel` | Что записывать: `debug`, `info`, `warning` или `error` | `info` |
| `logRetentionDays` | Сколько дней хранить файлы журнала, `0` значит всегда | `30` |
