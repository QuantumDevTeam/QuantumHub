# QuantumHub.Gui

Админка на WinUI 3. Как сайт-админка к серверу: своего состояния не имеет и подключается к хабу обычным клиентом.
Если хаб не запущен, GUI запускает его сам, а если хаб упал, поднимает снова. Завершённый из настроек хаб остаётся выключенным.

Хаб ищется рядом с GUI, а в репозитории — в `artifacts/QuantumHub`, потом в `bin`.

Сборка unpackaged: обычный exe без MSIX, файлы Windows App SDK лежат рядом.

| Файл | Что внутри |
|---|---|
| `App.xaml.cs` | Запуск, единственность экземпляра, трей |
| `MainWindow.xaml(.cs)` | Окно и навигация. Плагины появляются в панели сами |
| `Fluent.cs` | Общие блоки: карточка, заголовок, метка состояния |
| `Rendering/UiRenderer.cs` | **Рисует декларативный интерфейс плагинов** |
| `Pages/` | Страницы. `PluginPage` собирает страницу плагина |
| `Services/HubConnection.cs` | Связь с хабом, поиск и запуск его exe |
| `Services/PendingInstalls.cs` | Файлы плагинов, открытые из проводника |
| `Services/GuiSettings.cs` | Настройки окна. Без WinUI, поэтому проверяется тестами |
| `Services/WindowPlacement.cs` | Размер и место окна |
| `Services/NativeUiLoader.cs` | Загрузка UI-DLL плагина |
| `Services/TrayIcon.cs` | Значок в трее на чистом WinAPI |
| `Services/Autostart.cs` | Автозапуск через ключ `Run` |

Страницы собраны кодом, а не XAML: у них почти нет статичной разметки, и всё строится из данных хаба.

## Аргументы

| Аргумент | Что делает |
|---|---|
| `--minimized` | Стартует только в трее |
| `--instance <имя>` | К какому экземпляру хаба подключаться |
| `--page <тег>` | Какую страницу открыть, например `plugin:qh.sample.uuid` |
| `--service-args "<аргументы>"` | С чем запускать хаб, если GUI запускает его сам |
| `--install <файл>` | Установить плагин. Так открываются файлы `.qhp`. Если GUI уже запущен, файл передаётся ему |

Ошибки попадают в `%APPDATA%\QuantumHub\logs\gui.log`.

## Настройки

Настройки окна лежат в `%APPDATA%\QuantumHub\gui.<экземпляр>.json`, отдельно от хаба: они нужны ещё до подключения к нему.
Значения проверяются при чтении, так что испорченный файл только возвращает значения по умолчанию.

Чтобы добавить настройку, нужно свойство в `GuiSettings`, строка на `SettingsPage` и место, где она применяется. Что меняется на лету,
применяет `MainWindow.ApplySettings`, остальное страницы читают при создании. То, что программа запоминает сама, например
последнюю страницу, сохраняется через `GuiSettings.Note`: окну от этого перестраиваться незачем.

Тема задаётся только при запуске: кисти, которые страницы берут из кода, зависят от темы приложения, а её нельзя сменить на лету.
Поэтому после смены темы страница предлагает перезапустить окно, хаб при этом продолжает работать.
