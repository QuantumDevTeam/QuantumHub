# QuantumHub.Setup

Установщик и деинсталлятор в одном exe. Собирается скриптом `scripts/release.ps1`.

Работает там, где ещё ничего нет: сам он собран одним файлом вместе с рантаймом, а права администратора ему не нужны,
потому что всё ставится для текущего пользователя.

## Как устроен

Архив с программой дописан в конец exe. Если архив на месте, exe устанавливает, а если нет, удаляет. Поэтому `Uninstall.exe`
в папке программы — это тот же файл без архива.

| Файл | Что внутри |
|---|---|
| `Program.cs` | Сценарии установки и удаления, аргументы |
| `Payload.cs` | Архив в конце exe |
| `Installer.cs` | Работа с файлами. Без окон и реестра, поэтому проверяется тестами |
| `RunningApp.cs` | Закрывает программу перед заменой файлов |
| `ShellIntegration.cs` | Ярлык, список программ, автозапуск, файлы `.qhp` |
| `Dialogs.cs` | Окна на TaskDialog: так установщику не нужны ни WPF, ни WinForms |

## Что сохраняется

При обновлении заменяется всё, кроме плагинов, которых нет в архиве: их поставил пользователь. Настройки лежат в
`%APPDATA%\QuantumHub`, и их не трогает ни обновление, ни удаление. Плагин из комплекта, удалённый пользователем,
после обновления вернётся.

Перед заменой файлов закрываются только процессы из папки программы. Хаб получает просьбу завершиться, чтобы плагины
успели вернуть всё на место, и только потом завершается силой. В папке, где нет нашего `QuantumHub.Service.exe`, ничего
не удаляется: её могли выбрать по ошибке.

## Аргументы

| Аргумент | Что делает |
|---|---|
| `--silent` | Работает без окон |
| `--dir <папка>` | Папка программы |
| `--no-launch` | Не запускать программу после установки |
| `--no-autostart` | Не включать запуск вместе с Windows |
