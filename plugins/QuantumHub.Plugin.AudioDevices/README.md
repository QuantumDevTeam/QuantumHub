# Audio Devices

Id: `qh.audio`. Вид: папка с манифестом и зависимостью NAudio. Предоставляет возможность `audio.devices`.

Звуковые устройства и приложения со звуком как сервис. Про VR ничего не знает: им может пользоваться любой плагин или внешняя программа.

## API

Адрес `cap:audio.devices`, формат JSON.

| Метод | Запрос | Ответ |
|---|---|---|
| `devices.current` | нет | `{ "playback": { "id", "name" }, "recording": { "id", "name" } }` |
| `devices.list` | нет | `{ "playback": [ ... ], "recording": [ ... ] }` |
| `devices.set` | `{ "id": "..." }` | нет |
| `sessions.list` | нет | `[ { "process", "volume", "peak", "muted" } ]` |
| `sessions.volume` | `{ "process", "volume", "fadeMs" }` | нет |
| `mics.levels` | `{ "ids": [ ... ] }` | `[ { "id", "name", "bluetooth", "isDefault", "peak", "listening" } ]` |

Событие `audio.default.changed` приходит с телом как у `devices.current`, кто бы ни сменил устройство: плагин, другая
программа или пользователь в Windows. Изменение замечается в течение двух секунд.

```csharp
var current = await client.CallAsync("cap:audio.devices", "devices.current");
Console.WriteLine(current.AsText());
```

`sessions.list` показывает приложения, в которых сейчас идёт звук, по всем устройствам. `peak` — настоящий уровень сигнала:
больше нуля значит, что приложение правда звучит, а не просто держит сессию открытой. Приложение с несколькими
процессами сводится в одну запись, поэтому работать с ним нужно по имени, а не по PID.

Переключение идёт на все три роли Windows: Console, Multimedia и Communications.

## Уровни микрофонов

Счётчик уровня показывает настоящий сигнал, только пока поток записи этого микрофона кем-то открыт. Поэтому `mics.levels`
открывает поток для каждого id из `ids` и держит его, пока этот id спрашивают. Закрывать отдельно не нужно: примерно через
три секунды без вопросов микрофон отпускается сам, так что упавший клиент не оставит его занятым. Звук никуда не идёт и не сохраняется.

Ответ всегда содержит все активные микрофоны, а `listening` говорит, настоящий ли у него `peak`. Запрос без `ids` только показывает
список и ничего не открывает. С него и надо начинать, чтобы не занять лишнего.

- Пока поток открыт, Windows показывает значок использования микрофона, а в параметрах конфиденциальности виден хаб.
- `bluetooth: true` значит, что без спроса поток лучше не открывать: гарнитура уйдёт в режим HFP, и звук в ней станет
  телефонным. Определяется по шине устройства, а если её не удалось прочитать, по имени.
- Микрофон, который не открылся или оборвался, плагин пробует снова через десять секунд.

Список устройств обновляется раз в две секунды, поэтому новое устройство появляется с такой задержкой.
