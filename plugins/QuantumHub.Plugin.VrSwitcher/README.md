# VR Switcher

Id: `qh.vr.switcher`. Вид: папка с манифестом. Зависит от `audio.devices` ([Audio Devices](../QuantumHub.Plugin.AudioDevices/README.md)) и
`user.activity` ([User Activity](../QuantumHub.Plugin.Activity/README.md)), предоставляет `vr.session`.

Когда запускается SteamVR, переводит наушники и микрофон на гарнитуру, а после его закрытия возвращает как было.

## Как это работает

- О запуске VR плагин узнаёт от User Activity, сам за процессами не следит. Какие процессы считать VR, настраивается там.
- Если устройства гарнитуры появляются позже SteamVR, плагин ждёт их и пробует снова.
- После успешного переключения плагин больше не вмешивается: сменишь устройство сам, и он не будет спорить.
- Короткая пропажа SteamVR, например его перезапуск, не дёргает звук: нужны три пропущенные проверки подряд.
- Прежние устройства сохраняются в конфиге. Если хаб упадёт посреди VR, при следующем запуске звук вернётся.
- При остановке плагина звук тоже возвращается.

## Пресеты

| Пресет | Какие устройства ищет | Проверен |
|---|---|---|
| `Pico` | Имя содержит `Pico Streaming` без учёта пробелов и регистра | Имена взяты с настоящего Pico 4 Ultra |
| `Meta` | `Oculus Virtual Audio`, `Meta Virtual Audio` | Нет, имена взяты по памяти. Если не найдёт, используй `Custom` |
| `Custom` | Два поля в настройках | |

Все устройства показаны на странице плагина Audio Devices, оттуда удобно брать имена для `Custom`.

Поля «После VR» заставляют всегда возвращаться на конкретные устройства. Это нужно, если хаб запущен уже в VR и
плагин не знает, что было до него.

## API

Адрес `cap:vr.session`, формат JSON.

| Что | Описание |
|---|---|
| Метод `session.get` | `{ "active": true, "preset": "Pico", "onHeadset": true, "status": "..." }` |
| Событие `vr.session.changed` | То же самое, при начале и конце сессии |

Какое устройство используется сейчас, отвечает `cap:audio.devices` методом `devices.current`.

```csharp
var session = await client.CallAsync("cap:vr.session", "session.get");
var devices = await client.CallAsync("cap:audio.devices", "devices.current");
```

## Важно

Не держи автопереключение одновременно здесь и в VRAutomizer: они будут мешать друг другу.
