# Pico Sleep Mode

Id: `qh.vr.pico.antisleep`. Вид: папка с манифестом. Аддон к [VR Switcher](../QuantumHub.Plugin.VrSwitcher/README.md).

Не даёт шлему заснуть: регулярно шлёт ему `input keyevent 224` (WAKEUP) по ADB через Wi-Fi. Это тот же цикл, что в
рабочем скрипте `PicoWakeupWiFi.ps1`, и тот же режим, что «SleepMode» в трее VRAutomizer.

Про запуск SteamVR аддон узнаёт от VR Switcher через возможность `vr.session`, поэтому зависит от него. Включается кнопкой
на странице плагина или сам вместе с SteamVR, если включить настройку.

## Что нужно

1. **adb.exe.** В комплект не входит. Укажи путь в настройке, положи в папку плагина или добавь в PATH.
2. **ADB по сети на шлеме.** После перезагрузки шлема он выключен, и нужен кабель один раз. Плагин заметит кабель сам:
   выполнит `adb tcpip 5555`, узнает у шлема его адрес и подключится. Если шлем стримит по кабелю, учти, что
   `tcpip` перезапускает ADB на шлеме.

## Чем отличается от SleepMode в VRAutomizer

| Проблема там | Здесь |
|---|---|
| В настройках IP `.151`, а шлем на `.150` | По умолчанию `.150`, адрес можно уточнить через кабель |
| Нет шага `adb tcpip 5555` из скрипта | Выполняется сам, если есть кабель |
| Чтение вывода adb может зависнуть, потому что сервер adb наследует потоки | Сервер запускается отдельно, чтение с таймаутом |
| Команды без `-s`: с кабелем и Wi-Fi вместе adb откажется работать | Всегда указывается устройство |
| Если `disconnect` вернул ошибку, `connect` не вызывается вовсе | Подключение повторяется в любом случае |
| Первый сигнал только через минуту | Сразу |
| После 10 ошибок таймер останавливается навсегда | Цикл не сдаётся, как и скрипт |
